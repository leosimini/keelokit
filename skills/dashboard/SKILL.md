# Dashboard — one page, rebuilt from the repo every time

The page is generated by a script, never written by hand: that keeps every Keelokit page
identical in look (`references/design.md`) and true to the repo. Nothing is stored in the page;
regenerating it is always safe.

## 1. Build

1. Project root: the nearest directory with `.keelokit/` (walk up from the cwd). During kickstart,
   the product folder.
2. Language: `[dashboard] lang` in `.keelokit/state.toml` — the language of the interview. If it
   is missing, add it (`lang = "es"` or `"en"`); it is the only setting the page reads.
3. Run:
   ```bash
   python3 "${CLAUDE_PLUGIN_ROOT}/skills/dashboard/scripts/dashboard.py" --root <root>
   ```
   It writes `.keelokit/out/dashboard.html` (git-ignored by the folder's own `.gitignore`) and
   prints the path. `--json` prints the computed state (stages, stories, next step) without HTML.

## 2. Show it

- **Artifact tool available** → publish `.keelokit/out/dashboard.html` (icon `dashboard`,
  description "Where <product> is in the Keelokit process and what waits for you.").
  - First publish in the project: save the returned link in `.keelokit/state.toml` as
    `[dashboard] url = "<link>"`, so every later session updates the same page.
  - `url` already saved and not yet published in this conversation: read it first
    (`action: "read"`), then publish with that `url`. Within one conversation, republish the
    same file path.
  - The page is private; it contains the product's documents. Share it only if the user asks.
- **No Artifact tool, or the publish fails** → run the script again with `--standalone` (it
  writes a full HTML document) and give the user that file's path to open in a browser. The
  default output is only for the Artifact tool; don't hand it to the user.

## 3. Say it in the chat too

The page never replaces the question. With the link, write in the user's language (in Spanish,
waves are **olas de desarrollo**), in at most eight lines:
- where the project is and the section to look at (`#stage-<gate>` anchors: `stage-intake`,
  `stage-product`, `stage-stack`, `stage-skeleton`, `stage-adopt`, `stage-backlog`, `stage-build`);
- what exactly is up for approval, in short (the scope in/out and the metrics; the apps; the
  waves and their stories) — never "do you approve?" without saying what;
- the next step and its command.

## When other skills call it

After every gate is prepared (before asking for approval), after each approval, after a story
lands, after a wave, and when a session resumes a half-finished process. Publishing is a refresh:
it doesn't need the user's permission once the first page exists.

The next step on the page is a command to copy into the chat (`/keelokit:build AGENDA-002`,
`/keelokit:kickstart`); the page itself can't start work in the session.
